fix: ThreadIOBackend 的 pending 配平 + 文件原语跨平台化（Windows 启用暂缓）

往 Windows 移植线程池后端时挖出一个既有 bug 和一个进行中的问题。

修掉的 bug：
* m_pending 四条完成路径只 fetch_add、从不配平，close_impl 注释写着「完成路径
  会 release m_close_wake」但实际没人做 —— 于是每次 close() 都白等满
  close_timeout_ms，然后在池任务仍在飞时强制关句柄，WriteFile/ReadFile 打在
  已关闭（或已复用）的句柄上。现在统一 complete_pending()：递减 + 唤醒。

跨平台化（POSIX 行为不变）：
* 新增 utils/native_file.hpp：file_open/pread/pwrite/size/fsync/truncate/close/
  is_append。POSIX 直调；Windows 用 CreateFileW(FILE_FLAG_OVERLAPPED) +
  ReadFile/WriteFile(OVERLAPPED) + GetOverlappedResult 做定位 I/O。
* 错误码改用平台原生（errno / GetLastError），与 complete_error 的映射一致。

Windows 上暂不启用该后端：
* 原语层与 fileno()（复制句柄语义）已就位、可本地编译，但 backend 指向
  thread_pool 跑全套用例仍 access violation，且有一次运行内存冲到 16 GB。
* 因此 CMake 暂不编 thread_io_backend.cpp 到 Windows，discover 的可用性判定
  仍为 false —— configure({"backend": "thread_pool"}) 在 Windows 上继续报不可用。
* POSIX 侧由 CI 30 个 job 验证；本地 Windows 默认后端 226 passed / 4 skipped。
